LLM Context: Interpretable Forecasting Project

Purpose
- Build an interpretable multivariate time-series forecasting system that combines univariate function learners, temporal self-attention, cross-variable attention, temporal compression, and a spline-based forecasting head. We benchmark against strong baselines (LSTM, TCN, seasonal naive) on ETTh1 while emphasizing interpretability artifacts (attention maps, spline control points, basis functions) and clean data handling.

Core Goals
- Accurate multi-horizon forecasting on ETTh1 with consistent data splits and normalization.
- First-class interpretability: expose temporal attention, cross-variable attention, compression weights, and B-spline parameters for forecasts.
- Reproducible experiments with clear outputs and standardized directory structure.

Dataset
- ETT (Electricity Transformer Temperature) dataset (hourly) with 7 variables: HUFL, HULL, MUFL, MULL, LUFL, LULL, OT.
- Files in: interpretable_forecasting/ETT-small/ (ETTh1.csv, ETTh2.csv, ETTm1.csv, ETTm2.csv).
- Default experiment setup used in this repo:
  - input_length=96, forecast_horizon=24, stride=1
  - temporal split ratios: train=0.7, val=0.2, test=0.1
  - normalization: standard (fit on train only, applied to val/test)

Repository Structure (top-level under interpretable_forecasting/)
- benchmarks/test_models/: LSTM/TCN/seasonal-naive implementations and training utilities for baselines.
- benchmark_eval.py: Orchestrates all three baselines with consistent config and outputs to benchmark_outputs/.
- benchmark_outputs/: Timestamped baseline runs (lstm_baseline/, tcn_baseline/, seasonal_naive/).
- main model/: Extended interpretable model code and scripts.
  - extended_model.py, model.py: Model implementations.
  - data_utils.py, data_splitting.py: Data loading/splitting utilities for forecasting windows.
  - evaluation_utils.py: Metrics and denormalization helpers.
  - train_extended_model.py: Full training loop for the extended model.
  - validate_extended_model.py, validate_model.py: Validation/end-to-end checks and visualizations.
  - tests: test_* files covering data pipeline, spline learner, attention integration, etc.
  - training_outputs/: Timestamped extended-model training runs with configs and interpretability artifacts.
- model_eval_outputs/: Structured evaluation runs for curated extended-model configs (spline-only/residual variants).
- visualizations/: Visualization scripts (spline, attention, integrated model views).
- GAM/: Simple GAM exploration and plots for comparison/perspective.
- readmes/: Deep dives into architecture pieces and visualizations.
- README.md: Detailed documentation and quick start (already comprehensive).

Running Baselines (consistent ETTh1 setup)
- Single entry point (prefers local venv if present):
  - python benchmark_eval.py --epochs 50
- Produces outputs under benchmark_outputs/:
  - benchmark_outputs/lstm_baseline/<timestamp>/
  - benchmark_outputs/tcn_baseline/<timestamp>/
  - benchmark_outputs/seasonal_naive/<timestamp>/
- Each run includes: config.json, results.json (train/val history), test_results.json (final test metrics), forecast_examples.png, and checkpoints/best.pt when applicable.

Baseline Model Configs (as used in the attached results)
- LSTM: hidden_size=128, num_layers=2, dropout=0.1, bidirectional=false; batch_size=32; lr=1e-3; epochs=50.
- TCN: channels=[64,64,64], kernel_size=3, dropout=0.1; batch_size=32; lr=1e-3; epochs=50.
- Seasonal Naive: season_length=24.
- Shared: input_length=96, forecast_horizon=24, stride=1, normalize=standard, seed=42, device=cuda if available.

Running the Extended Interpretable Model
- Train (example from README; adjust flags as needed):
  - cd interpretable_forecasting
  - python "main model/train_extended_model.py" --data-path "ETT-small/ETTh1.csv" --input-length 96 --forecast-horizon 24 --batch-size 32 --epochs 50 --lr 5e-4 --num-compression-queries 2 --num-control-points 16 --spline-smooth-alpha 0.3 --no-residual-head
- Key CLI flags (train_extended_model.py):
  - Data: --data-path, --input-length, --forecast-horizon, --stride, --train-ratio, --val-ratio, --test-ratio
  - Model: --embed-dim, --hidden-dim, --num-heads, --cross-dim, --cross-heads, --compressed-dim, --num-control-points, --dropout, --num-compression-queries, --spline-smooth-alpha, --no-spline-head, --no-residual-head
  - Training: --epochs, --batch-size, --lr, --weight-decay, --scheduler, --warmup-epochs
  - Logging: --save-dir (default main model/training_outputs), --save-freq (default 5), --patience (default 10)
- Artifacts saved under main model/training_outputs/<timestamp>/:
  - config.json (full CLI config), best_model.pt, test_results.json, interpretability/ (val_attention_epoch_*.png, splines_val_epoch_*/ and splines_test_final_epoch_*/ subfolders, training_curves.png).

Extended Model Architecture (very high level)
- Univariate Function Learners: per-variable MLPs for embeddings.
- Temporal Self-Attention: captures intra-variable temporal dependencies with interpretable attention matrices.
+- Cross-Variable Attention: variable-to-variable relationships (M×M), interpretable heatmaps.
+- Temporal Compression: attention-based pooling to compressed_dim; exposes compression attention.
+- Spline Function Learner: predicts B-spline control points to generate horizon-length forecasts. Exposes control points, basis functions, knot vectors.
- Optional Residual Head: linear residual on top of spline forecasts for accuracy/robustness trade-offs.

Evaluation Conventions
- Metrics computed on denormalized scale: MSE, MAE, RMSE, MAPE.
- Validation history stored in results.json for baselines; extended model stores history inside best checkpoint and plots under interpretability/.
- Test metrics saved to test_results.json for both baselines and extended model variants.

Outputs and Where to Find Them
- Baselines: benchmark_outputs/<model>/<timestamp>/
  - config.json, results.json (full training/val history), test_results.json (final denormalized metrics), forecast_examples.png, checkpoints/best.pt.
- Extended model: main model/training_outputs/<timestamp>/
  - config.json, best_model.pt, test_results.json, interpretability/ (attention maps and spline visualization folders), training_curves.png.
- Curated evaluations: model_eval_outputs/<experiment_name>/<timestamp>/ with the same artifact structure.

Data & Preprocessing Invariants
- Splits are strictly temporal; no leakage across train/val/test.
- Normalization is computed on train only; cached statistics are applied to val/test and used to denormalize outputs for metrics and visualizations.
- Forecasting windows produced via ETTDataSplitter.get_forecasting_data for each split.

Interpretablity Artifacts
- Temporal attention (per variable), Cross-variable attention (M×M), Compression attention (time-step importances).
- Spline parameters: control points, basis functions, knot vectors.
- Visualizations saved periodically (by --save-freq) and at test time (splines_test_final_epoch_*).

How To Extend
- New datasets: add loaders/splitters in main model/data_utils.py and data_splitting.py; ensure train-only normalization and denorm for metrics.
- New baselines: add a script in benchmarks/test_models/ and wire it in benchmark_eval.py to ensure consistent configs and outputs.
- New model variants: extend ExtendedModelConfig and InterpretableForecastingModel; expose new interpretability keys in output['interpretability'].

Conventions & Defaults
- Seed=42, device=cuda if available; PyTorch Adam optimizer; optional ReduceLROnPlateau scheduler; gradient clipping to max_norm=1.0.
- Metrics reported as floats; note that MAPE values reported in current runs are large numeric values as stored (use as-is for comparison within this repo).
